## 🐚 О проекте

**PetShell (OceanShell)** — модульный эмулятор UNIX-подобной командной строки,  
созданный в рамках учебного проекта, но оформленный в стиле фирменной морской тематики **ASDINC**.  

Система полностью работает в памяти, поддерживает собственную **виртуальную файловую систему (VFS)**,  
настраиваемые приглашения (`prompt`), обработку скриптов, встроенные команды и базовый парсер,  
который умеет понимать аргументы в кавычках — как в настоящем UNIX-терминале.

## ⚙️ Архитектура модулей OceanShell
🌊 OceanShell.sln
└── src/
├── 💬 GuraShell    — CLI-интерфейс, точка входа (эмулятор терминала)
├── 🧠 SabaSaba     — маршрутизатор команд (мозг)
├── 💧 AquaParse    — парсер аргументов и токенайзер
├── 📁 LilyFS       — виртуальная файловая система (VFS)
├── 🌸 RuiSys       — системная информация и World Flower API
└── 🎨 FinPrompt    — визуальный стиль, цвета и сборка приглашения

💬 GuraShell
 ├─→ FinPrompt   — создаёт визуальное приглашение
 ├─→ AquaParse   — токенизация пользовательского ввода
 ├─→ SabaSaba    — маршрутизация и выполнение команд
 └─→ ScriptRunner — поддержка тестовых сценариев

🧠 SabaSaba
 ├─→ LilyFS      — операции VFS (ls, cd, rm, rmdir)
 ├─→ RuiSys      — получение данных пользователя/хоста
 └─→ Builtins    — обработка встроенных команд

📁 LilyFS
 ├─ управляет деревом виртуальной файловой системы
 └─ хранит текущее состояние каталога (cwd)

💧 AquaParse
 └─ разбивает строку на токены, учитывая кавычки и экранирование

🎨 FinPrompt
 └─ собирает итоговое приглашение: user@host[GawrShell]:~%

## 🧱 Этапы разработки

### **Этап 1. Базовая оболочка и REPL**
- Создана консольная программа `GuraShell`, реализующая цикл `read–eval–print–loop`.
- Реализовано приглашение в стиле UNIX:  
  `username@hostname[GawrShell:~%`
- Добавлен парсер `AquaParse.Tokenizer`:
  - поддержка `"..."`, `'...'`, `\экранирования`;
  - вывод ошибок разбора (незакрытые кавычки);
  - корректная работа с пробелами и пустыми токенами.

🧪 **Тест:** `scripts/test-all.gsh` — проверка парсера, кавычек и ошибок.

---

### **Этап 2. Аргументы командной строки и стартовые скрипты**
- Добавлена поддержка флагов запуска:
  - `--vfs-path <dir>` — путь к виртуальной файловой системе;
  - `--script <path>` — путь к стартовому скрипту.
- Реализован `ScriptRunner` — обработчик файлов `.gsh`,  
  который имитирует ввод пользователя построчно.
- Поддерживаются комментарии `//` и `/* ... */`.
- Исполняется скрипт с эмуляцией вывода и парсингом каждой команды.

🧪 **Тест:**  
`scripts/test-all.gsh` — демонстрирует работу скриптов, комментариев и ошибок парсера.

---

### **Этап 3. Виртуальная файловая система (VFS)**
- Реализована модель `LilyFS` с хранением структуры в памяти.
- Загрузка файловой системы из JSON (base64-контент).
- Команда `vfs-init`:
  - без аргументов — сброс до пустой VFS;
  - с путём — загрузка указанного JSON.
- Обработка ошибок загрузки: отсутствующий файл, битый JSON.
- Поддержка нескольких тестовых VFS: `minimal.json`, `multi.json`, `deep.json`.

🧪 **Тест:**  
`scripts/test-vfs.gsh` — проверка загрузки разных VFS и ошибок инициализации.

---

### **Этап 4. Основные UNIX-команды**
Реализованы команды:

| Команда | Назначение |
|----------|-------------|
| `ls [path]` | просмотр содержимого директории |
| `cd [path]` | переход между каталогами |
| `pwd` | показать текущий путь |
| `date [+"format"]` | показать дату и время |
| `cal [month] [year]` | календарь на месяц |

Дополнительно:
- Поддержка `.` `..` и `~` в путях.
- Нормализация абсолютных и относительных путей.
- Вывод ошибок при неправильных аргументах и неинициализированной VFS.

🧪 **Тест:**  
`scripts/test-core.gsh` — проверка всех команд и навигации по виртуальному дереву.

---

### **Этап 5. Модифицирующие команды**
Реализованы команды, изменяющие состояние VFS (в памяти):

| Команда | Назначение |
|----------|-------------|
| `rm <file>` | удалить файл |
| `rmdir <dir>` | удалить пустой каталог |

Ограничения:
- Нельзя удалить корень `/`;
- `rm` не удаляет каталоги;
- `rmdir` отказывает, если каталог не пуст.

🧪 **Тест:**  
`scripts/test-mutate.gsh` — проверка всех режимов `rm` и `rmdir`,  
включая успешные и ошибочные случаи.
